# Capture policy

Controls whether prompt/completion content (`gen_ai.input.messages` /
`gen_ai.output.messages`) is allowed to reach the backend. Everything else the
Collector redacts (auth headers, cookies, API keys, raw SQL,
`gen_ai.system_instructions`, hashed identifiers) applies regardless of policy.

## Files

| File | Purpose |
|---|---|
| `policy.schema.json` | The shape a policy file must match. |
| `metadata-only.yaml` | Default. Content is deleted before export. |
| `content-approved.yaml` | Content is allowed through. |
| `apply.sh` | Applies a policy. |
| `.env.active` | Generated by `apply.sh` (gitignored). |

## How it works

```bash
./apply.sh content-approved
./apply.sh metadata-only
```

`apply.sh` writes the selected mode into `CAPTURE_MODE` and recreates the
Collector container so it takes effect. The Collector reads `CAPTURE_MODE` at
startup, so switching the policy restarts the Collector (a brief telemetry gap)
but never the application — stdout logging and request serving continue
throughout. A truly hot-reloadable policy would need something like OpAMP, which
is out of scope here.

Content attributes are gated by the Collector even before the app emits any, so
the switch is verifiable now (`otel/tests/test_policy_switch.sh` uses
hand-crafted spans that carry them).
